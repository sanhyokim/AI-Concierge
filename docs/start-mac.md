# はじめての起動（Mac）

管理画面とブラウザー会話試験を、自分のMacで動かす手順です。**ターミナルにコマンドを入力する必要はありません。** 上から順に行ってください。

- 対象：macOS 12 以降。ブラウザーは Chrome・Edge・Safari のどれか。マイク付きのヘッドセット（推奨）。
- かかる時間：初回は約15分（Pythonを入れる時間を含む）。
- この手順で、会社の回線やLINEにつながることはありません。手順3までは、費用もかかりません。

---

## 手順1　Python を入れる（最初の1回だけ）

Mac に最初から入っている Python は古い（3.9）か、入っていないため、新しいものを入れます。

1. ブラウザーで https://www.python.org/downloads/ を開きます。
2. 黄色い「**Download Python 3.13**」（3.11 以上なら、ほかの番号でもかまいません）を押します。
3. ダウンロードした `python-3.13.x-macos11.pkg` を開き、「続ける」「同意する」「インストール」と進めます（Macのパスワードを聞かれたら入力します）。
4. **最後に開くフォルダー（Python 3.13）の「Install Certificates.command」をダブルクリックします。** ターミナルの画面に英語の文字が流れ、「[Process completed]」などと出たら、その画面は閉じてかまいません。
   - これは、OpenAI などとの通信（HTTPS）で相手を確かめるための証明書を、Python に入れる作業です。行わないと、試験の開始で「URLError」「CERTIFICATE_VERIFY_FAILED」と出て、AIにつながりません。
   - フォルダーを閉じてしまったときは、Finder →「アプリケーション」→「Python 3.13」の中にあります。
   - 忘れても、`start_mac.command` が起動のたびに確かめ、Mac 本体の証明書で代わりに動かします。それでもだめなときは、このファイルを案内します。

## 手順2　プログラムをダウンロードする

1. ブラウザーで GitHub に**ログインした状態で**、次のアドレスを開きます。ZIPファイルのダウンロードが始まります。

   https://github.com/sanhyokim/AI-Concierge/archive/refs/heads/claude/new-session-w4sjel.zip

   - 「404」と出たときは、GitHub にログインしていません。ログインしてから、もう一度開きます。
2. 「ダウンロード」フォルダーに `AI-Concierge-claude-new-session-w4sjel.zip` ができます（Safari では、自動で展開されて同じ名前のフォルダーになることもあります。どちらでもかまいません）。

## 手順3　起動して、オフラインの模擬で動作を確かめる（APIキー不要・費用0円）

起動には `AI受付を起動_mac.command` を使います。このファイルは、「ダウンロード」フォルダーの新しいZIPを、ホームフォルダーの `AI-Concierge` に入れてから起動します。Mac の確認（「開いていません」の画面）は、**最初の1回だけ**です。新しい版をダウンロードしても、もう出ません。記録と管理画面のパスワードも引き継ぎます。

1. **最初の1回だけ**、次のようにします。
   1. ZIP をダブルクリックして展開します（Safari が展開済みなら不要です）。できたフォルダーの中の `AI受付を起動_mac.command` を**ダブルクリック**します。
   2. **「"AI受付を起動_mac.command"は開いていません」と出て、ボタンが「ゴミ箱に入れる」と「完了」だけのとき**（macOS 15 Sequoia 以降）：
      - **「完了」**を押します。「ゴミ箱に入れる」は押さないでください。
      - アップルメニュー →「**システム設定**」→ 左の「**プライバシーとセキュリティ**」を開きます。
      - 右側を一番下のほうまでスクロールし、「"AI受付を起動_mac.command"は Mac を保護するためにブロックされました」の横の「**このまま開く**」を押します。Mac のパスワード（または Touch ID）を求められたら入力します。
      - もう一度ダブルクリックし、確認の画面で「**このまま開く**」を押します。
   3. **「開発元を確認できないため開けません」と出て、「開く」のボタンがないとき**（macOS 14 以前）：右クリック（または control キーを押しながらクリック）→「開く」を選び、出た画面で「**開く**」を押します。
   4. 「"ターミナル"から"ダウンロード"フォルダ内のファイルにアクセスしようとしています」と出たら、「**許可**」を押します。
   5. ターミナルに「入れました：…/AI-Concierge」と出て、そのまま起動します。
   6. 次回のために、Finder のメニュー「移動」→「ホーム」を開き、`AI受付を起動_mac.command` を **Dock の右側（ゴミ箱の近く）にドラッグ**しておきます。
   - 展開したフォルダーとZIPは、この後は使いません（捨ててかまいません）。
2. **2回目から**は、Dock（またはホームフォルダー）の `AI受付を起動_mac.command` をクリックするだけです。
   - **新しい版に入れ替えるとき**：手順2のとおりZIPをダウンロードしてから（展開は不要）、同じようにクリックします。新しいほうを自動で入れて起動します。前のフォルダーを捨てる必要はありません。
   - 新しいダウンロードがないときは、「新しいダウンロードはありません。いまの版で起動します。」と出て、そのまま起動します。
2. 「ターミナル」の画面で、**最初の1回だけ**、管理画面のパスワードを決めます（入れ替えの後も、同じパスワードのまま使えます）。
   - 「管理画面のパスワードを決めて入力し、Enter」と出たら、8文字以上のパスワードを入力して return キーを押します。**入力しても画面には何も表示されませんが、入っています。**
   - 「同じパスワードをもう一度」と出たら、同じものを入力して return キーを押します。
   - このパスワードは控えておいてください（ユーザー名は `admin` です）。
3. APIキーを聞かれます。**今回は何も入力せずに return キーを2回**押します。
4. 「準備ができました」と出て、ブラウザーが開きます。
   - 「"Python" に受信接続を許可しますか？」と出たら、「拒否」でかまいません（このMacの中だけで使うため）。
   - ブラウザーが開かないときは、ブラウザーの住所の欄に `http://127.0.0.1:8780/lab/` と入力します。
5. ユーザー名 `admin` と、決めたパスワードでログインします。
6. 「ブラウザー会話試験」の画面が開きます。
   - マイクの使用を聞かれたら、**「許可」**を押します。
   - 候補で **「オフラインの模擬」** を選び、「会話を始める」を押します。ヘッドセットに向かって話すと「マイク」のメーターが動き、電子音が鳴ります。「終える」で終了します。
7. ここまでできれば、Macでの準備は完了です。**ターミナルの画面は、試験が終わるまで閉じないでください。** 閉じるとサーバーが止まります。

## 手順4以降

APIキーの用意、最初の会話、会話試験の段取り（C1〜C7）は、[はじめての起動（Windows）](./start-windows.md) の手順4・手順5と「会話試験の段取り」と同じです。次のところだけ、読み替えてください。

| Windows | Mac |
| --- | --- |
| `start_windows` をダブルクリック | Dock の `AI受付を起動_mac.command` をクリック |
| 黒い画面 | ターミナルの画面 |
| 貼り付けは Ctrl+V | 貼り付けは ⌘+V |
| Enter キー | return キー |
| `reset_password_windows`（パスワードを忘れたとき） | ホームの `AI-Concierge` フォルダーの `reset_password_mac.command`（確認は出ません） |
| 結果のファイル `prototype\results\browser-lab` | ホームの `AI-Concierge/prototype/results/browser-lab` |
| 毎回の貼り付けを省く（環境変数） | 行わず、毎回貼り付けます（パスワード管理ソフトに保管） |

## うまくいかないとき

| 画面に出たこと・起きたこと | 原因と対処 |
| --- | --- |
| 開いたら `@echo off` `chcp 65001` などの文字が表示された | Windows 用の `start_windows.bat` を開いています。閉じて、`AI受付を起動_mac.command` を開きます。見当たらないときは古いZIPなので、手順2のとおりダウンロードし直します |
| 「開始できませんでした：…: URLError」、または「CERTIFICATE_VERIFY_FAILED」「証明書を確かめられません」 | Python に HTTPS の証明書が入っていません。手順1の4（Install Certificates.command をダブルクリック）を行い、ターミナルの画面を閉じてから `AI受付を起動_mac.command` を開き直します。この失敗は OpenAI に届いていないため、回数にも費用にも数えません |
| GPT-Live 1 で「開始できませんでした：https://api.openai.com/v1/live/sessions: HTTP 400」（2026-10-19、Windows） | 一度だけの失敗のことがあります（この日は、直後にもう一度押すと harema でつながりました）。まず、もう一度「開始」を押します。最新版では、声が断られたときは自動で標準の声（marin）でつなぎ直し、会話試験の記録に「声 harema はOpenAIに断られたので、marin で話します」と残します。もう一度押しても同じ表示が出るときは、表示された文と、ターミナルの画面の「[会話試験] … 接続に失敗」の行をすべてコピーして送ってください（断られた接続は、料金も回数もかかりません） |
| ターミナルに「インターネットにつながっていないようです」 | Wi-Fi などを確かめて、開き直します。つながらないままでも、オフラインの模擬は使えます |
| 「"AI受付を起動_mac.command"（または "start_mac.command"）は開いていません」「Apple は、…マルウェアが含まれていないことを検証できませんでした」（ボタンは「ゴミ箱に入れる」と「完了」だけ） | macOS 15 以降の、インターネットから落としたファイルを初めて開くときの確認です。ファイルは壊れていません。「完了」を押し、手順3の1のとおり「システム設定」→「プライバシーとセキュリティ」の「このまま開く」で開きます（2026-10-13、利用者のMacで発生）。ダウンロードのたびに出ていたので、`AI受付を起動_mac.command` で、確認を最初の1回だけにしました。2回目からは Dock かホームフォルダーのものを開きます |
| 新しい版をダウンロードしたのに、古いまま起動する | ZIP の名前が `AI-Concierge-claude-new-session-w4sjel` で始まり、「ダウンロード」フォルダーにあるかを確かめます。ターミナルに「新しいダウンロードを入れます」と出れば入っています |
| 「…/AI-Concierge を入れ替えられませんでした」 | 前に開いたターミナルの画面（サーバー）が残っています。閉じてから、もう一度クリックします |
| 「開発元を確認できないため開けません」 | 手順3の1のとおり、右クリック →「開く」で開きます（macOS 14 以前） |
| 「Python 3.11 以上が見つかりません」 | 手順1を行います。入れた後も同じなら、ターミナルの画面を閉じてから、もう一度開きます |
| 「このファイルは、ZIP を展開したフォルダーの中から開いてください」 | `AI受付を起動_mac.command` から開きます（手順3） |
| 「アクセス権がありません」「実行できません」 | ファイルの実行の許可が失われています。ZIPをダウンロードし直して、Macの標準の方法（ダブルクリック）で展開します |
| 「ポート 8780 が使われています」 | 前に開いたターミナルの画面が残っています。閉じてから、もう一度開きます |
| マイクのメーターが動かない | ① ブラウザーの住所の欄の左のアイコンで、マイクを「許可」。② アップルメニュー →「システム設定」→「プライバシーとセキュリティ」→「マイク」で、使っているブラウザーをオンにする。③ ヘッドセットを、Macの入力の機器にする（「システム設定」→「サウンド」→「入力」） |
| 会話を始めても電子音しか聞こえない | 候補が「オフラインの模擬」になっています。左の「通話」の **AI（候補）** で「OpenAI GPT-Live 1」などを選びます |
| ターミナルに英語のエラー（Traceback …）が出て止まった | `Traceback` から最後の行までをマウスでなぞって選び、⌘+C でコピーして、開発の担当（Claude）に送ってください。キーやパスワードは画面に表示されないので、そのまま送ってかまいません |

## 確認できていること・できていないこと

- 開発のサーバーで、起動のファイルの分かれ道（Pythonがない・古い・展開したフォルダーの外、証明書がない・Mac 本体の証明書で代わりに動かす・インターネットにつながらない）と、起動（パスワードとキーの入力からログインまで）を確かめています。
- 実際のMacでのダブルクリックからの起動は、開発のサーバーでは試せません。最初にお使いの画面で確かめていただく必要があります。
