## 1. 何ができるか

- 1つの画面で候補を切り替えて、マイクで実際に話せます。
- 受付業務・FAQ・業務処理（ツール）は全候補で共通です。業務処理は、管理画面と同じ**受付の共通処理**を通ります。
  - FAQ・声は、会話の開始時の管理画面の設定を使います。
  - 業務処理は、確認のガード（復唱の後の明確な肯定がない限り確定しない）を通ります。
  - 会話は受付履歴に「ブラウザー会話試験」として残ります。試験の会話では通知は作りません。
- 共通会話の台本C1〜C6のカードを選んでから話すと、記録がその台本に結びつきます。
- 計測は、**この端末の音量だけ**で行います。マイクの音とAIの再生音を別々に測るので、業者のイベントの違いに左右されません。
  - **応答の遅延**：お客様の発話が終わってから、AIの音が聞こえ始めるまで。
  - **割り込みの結果**：AIの発話中にお客様が話し始めたら、すべてに結果を付けて残します。測れなかったものや遅いものを、黙って除きません。
    - 2.5秒以内に停止
    - 遅い停止（2.5〜6秒。時間も記録）
    - 止まらず（6秒以内に停止なし。短い相づちだったかも区別）
    - 判定前に次の発話
    - 会話の終了で未判定
  - **停止までの中央値・p90**：測れたものだけで計算し、件数の内訳を並べて表示します。
  - **相づちで停止の可能性**：短い発話（0.6秒未満）の後にAIが止まったもの。自動の推定なので、判定欄の記入を正とします。
- 判定の欄は2つに分かれています。
  - **音声**：相づちで不要に止まった、訂正を取りこぼした、停止の求めに応じた、自然さ1〜5。
  - **業務処理**：番号・日時の復唱と確認が正しい、受付記録が会話と一致。
  - 保存すると、サーバーが業務処理を受け取った会話は「評価対象」になります。受け取らなかった会話は「未評価」と記録します。
- 「AIの拒否（模擬）」：お客様がAIでの処理を拒否した想定で、業者への接続を閉じます。以降の業務処理は、サーバーが拒否します。
- C5を選んでいる間は、業務処理を4秒遅らせます。1回の会話は最大4分で、自動的に切れます。

## 2. 動かし方（試験をする人のPC）

マイクは試験をする人のブラウザーにあるため、このクラウドの環境ではなく、**試験をする人のPC**で動かします。

**必要なもの**
- Python 3.11以上（追加のパッケージは不要）
- 新しいChromeまたはEdge
- ヘッドセット（推奨）。スピーカーで試す場合は、その条件を画面で選んで記録します。

**手順**
1. リポジトリを取得します（ブランチ `claude/new-session-w4sjel`）。
2. 使う構成の鍵を、**そのPCの環境変数**に設定します。鍵はチャットに貼らないでください。ファイルに書く場合も、リポジトリに入れないでください。

   | 構成 | 環境変数 |
   | --- | --- |
   | GPT-Live 1、GPT-Realtime-2.1 | `OPENAI_API_KEY`（GPT-Liveのバックエンドのモデルは `GPT_LIVE_DELEGATION_MODEL` で指定できる。既定は公式ガイドの例 `gpt-6-luna`） |
   | Gemini 3.8 Live | `GEMINI_API_KEY` |
   | ElevenAgents | `ELEVENLABS_API_KEY`、`ELEVENLABS_AGENT_ID` |
   | Cartesia Managed Agents | `CARTESIA_API_KEY`、`CARTESIA_AGENT_ID` |

3. 管理画面のサーバーを起動します。最初の起動で、ログインのパスワードが1回だけ表示されます。

   ```bash
   python3 -m prototype.admin
   ```

4. ブラウザーで `http://127.0.0.1:8780/lab/` を開き、ログインして、マイクの使用を許可します。
   - 単独でも動かせます：`python3 -m prototype.browser_lab` で起動し、`http://127.0.0.1:8765` を開きます。こちらはログインがなく、自分のPCの中だけで使います。

**段階と上限**

- 既定は、**接続の予備試験**の上限です（各候補1〜2回分）。
- 予備試験で動いた候補を詳しく比べるときは、`LAB_STAGE=detailed` を付けて起動します。

  ```bash
  LAB_STAGE=detailed python3 -m prototype.admin
  ```

- 上限は台帳で累計して守ります（[実測計画 v2.1](./measurement-plan-v2.md) 5章）。

**安全のための作り**

- **待ち受け**：サーバーは自分のPCの中（127.0.0.1）だけで待ち受けます。ほかのホスト名や、別のサイトからの要求は断ります。
- **ログイン**：管理画面経由では、ログインが必要です。更新の要求には、CSRFのトークンが要ります。
- **鍵**：鍵はブラウザーに渡しません。
  - サーバーが業者から**短時間だけ使える接続情報**（一時トークン、署名付きURLなど）を受け取り、その会話の接続のためだけに画面へ渡します。
  - GPT-Liveは、接続の交換そのものをサーバーが行います（1回の会話につき1回だけ）。
- **鍵がない構成**：画面で選べません。何も送りません。

**オフラインでの確認**

- 「オフラインの模擬」を選ぶと、業者に接続せずに、画面・計測・業務処理・保存の流れを確かめられます。
- 音はトーンで、何の声の評価にもなりません。

## 3. 業者ごとの準備

**共通**

- **プロジェクトと予算**：できるだけ試験専用のプロジェクトや鍵を作り、業者側でも予算と通知を設定します。業者側の予算が、上限で必ず止まるとは限りません。
  - 前払いのクレジットで自動の追加購入を切っておけば、残高が上限になります（OpenAI、Geminiの有料枠）。
- **アカウント**：新しいアカウントを作る場合は、新しい契約にあたります。作るかどうかを判断してください。
- **指示文**：指示文は、会話の開始時に管理画面のFAQから作ります。業者の画面に設定する必要がある構成では、次のコマンドで表示した文を貼り付けます。

  ```bash
  python3 -c "from prototype.browser_lab.config import GREETING, LAB_RULES; print(GREETING); print(); print(LAB_RULES)"
  ```

  - FAQの答えは、業務処理の `lookup_faq` が、その会話の開始時の設定から返します。管理画面でFAQを変えれば、業者の画面を変えなくても、次の会話から反映されます。
- **業務処理（ツール）**：次の5つです。

  | ツール | 引数 |
  | --- | --- |
  | `save_field` | `field`, `value` |
  | `request_readback` | `field` |
  | `confirm_field` | `field`, `value` |
  | `lookup_faq` | `question` |
  | `flag_emergency` | `level`, `reason` |

  - 定義は `python3 -c "import json; from prototype.reception.tooldefs import RECEPTION_TOOLS; print(json.dumps(RECEPTION_TOOLS, ensure_ascii=False, indent=1))"` で表示できます。

| 構成 | 業者側で行うこと | 業務処理の経路 | 試験での注意 |
| --- | --- | --- | --- |
| GPT-Live 1 | OpenAIの試験用プロジェクトの鍵。会話の設定は、サーバーが接続のときに送る | delegation（Responses）。バックエンドのモデルに5つのツールを関数として渡し、関数呼び出しは `response.event` でブラウザーに届く。ブラウザーが共通の処理へ送り、`response.item.create`＋`response.create` で返す | バックエンドのモデルは別料金（L_live）。声は `audio.output.voice`（日本語に合う声は未確認）。言語の設定欄はなく、指示文で日本語を指定する。発話・割り込みのイベントはないので、端末の計測だけを使う |
| GPT-Realtime-2.1（基準） | 同上。声は管理画面の設定（既定 `marin`） | 関数呼び出し | — |
| Gemini 3.8 Live | Google AI Studioの鍵。無料枠は入出力がGoogleの改善に使われる条件なので、架空のデータだけで使う。有料枠は前払い | 関数呼び出し（`toolCall`／`toolResponse`） | 履歴はターンごとに課金されるため、履歴を短く保つ設定（contextWindowCompression）を送る。声は管理画面の設定（`prebuiltVoiceConfig`） |
| ElevenAgents | ElevenLabsの画面でエージェントを作る：言語は日本語、Expressive mode、日本語の声、使うLLM（記録しておく）、指示文、最初のあいさつ。client tools として上の5つを登録する（応答を待つ）。割り込みのクライアントイベントを有効にする。エージェントを非公開にし、署名付きURLで接続する | client tools | 実際に選べるモデル・声・地域を記録する。Freeでclient toolsが使えるかは未確認 |
| Cartesia Managed Agents | Cartesiaの画面でエージェントを作る：音声認識はInk-2（日本語）、音声合成はSonic-3.6（日本語の声）、使うLLM（記録しておく）、指示文、最初のあいさつ。Playgroundの Tools で「Client function」として上の5つを作り、エージェントに付ける（応答を待つ） | client tools（新しいエージェントのWebSocket `/v1/agents/websocket`。`client_tool_call` → `client_tool_result`） | 旧い接続先（`/agents/stream`）にはツールのイベントがないため使わない。音声は16kHzのPCMで送受信。Webhookのツールも公式にあるが、公開のHTTPSのURLが要るため今回は使わない |

## 4. 試験の進め方

1. 候補と条件（ヘッドセット／スピーカー、エコー抑制、試験の回）を選び、「会話を始める」を押します。
2. 台本のカードを選び、カードに書いたとおりに話します。架空の情報だけを使います（[実測計画 v2.1](./measurement-plan-v2.md) 3章の試験用の情報）。
3. 終わったら「終える」を押し、判定の欄（音声・業務処理）とメモを記入して、「結果を保存」を押します。保存は1回の会話につき1回です。
4. 結果は `prototype/results/browser-lab/` に保存されます（gitの対象外）。中身は次のとおりです。
   - 業者の記録（文字起こし・イベント）
   - 端末の計測（割り込みごとの結果を含む）
   - 判定（音声と業務処理に分けたもの）
   - サーバーが記録した業務処理と受付の項目・要約
5. 会話の記録は、管理画面の受付履歴でも見られます（画面の「管理画面で開く」）。

## 5. 費用の管理

- **始める前**：会話を始める前に、台帳に「最大4分 × その構成の上限の分単価」を留保します。段階ごとの上限を超えるなら、始めずに止まります。
- **終えたとき**：時間（課金単位に切り上げ）× 上限の分単価を**推定**として記録し、留保を閉じます。
  - 時間は、画面が知らせた時間と、サーバーが見た接続の時間の長い方を使います。
  - 終えずに画面を閉じた会話は、留保したまま残ります。
- **照合**：試験の後、業者の利用画面の額で照合します。照合すると、その会話の合計が利用画面の額になります。同じ照合を二度しても、増えません。

  ```bash
  python3 -m prototype.engines.budget                     # 累計・開いたままの留保
  python3 -m prototype.engines.budget --close <留保ID> --vendor openai_lab --actual-usd 0.21 --note "利用画面で確認"
  ```

- 台帳は、こちら側の見積もりです。業者側の課金の上限を保証するものではありません。使用量が報告されなかった会話を、0円とは扱いません（留保を残します）。
