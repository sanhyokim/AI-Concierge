## 1. 最初の会話を始める手順（GPT-Live 1・Gemini 3.8 Live）

**始める前に決めること（利用者）**

| 事項 | 内容 |
| --- | --- |
| アカウント | OpenAI と Google AI Studio の2つだけ。ElevenLabs・Cartesiaは後回し |
| 支払い | OpenAIの前払い$5（残高がなければ。税抜）。Geminiは無料枠（架空のデータだけ。入出力がGoogleの改善に使われる条件）か、有料枠の前払い$5 |
| 回数 | 接続の予備試験は、各候補2回まで（サーバーが数えて守る） |
| 費用の見方 | 前払いの残高は、費用の上限ではありません（集計の遅れで超えることがある）。業者側でも予算と通知を設定する |

**手順1：起動とログイン**

1. 起動します。コマンドの入力は不要です。
   - **Windows**：[はじめての起動（Windows）](./start-windows.md) のとおり、展開したフォルダーの `start_windows` をダブルクリックします。
   - **mac・Linux**：ターミナルで展開したフォルダーへ移動し、`python3 -m prototype.admin --setup` を実行します。
2. 最初の起動では、管理画面のパスワードを決めます（2回入力。画面には表示されません）。
3. APIキーを聞かれたら、コピーしたキーを貼り付けて Enter を押します（画面には表示されません）。キーは、そのPCのメモリーにだけ置きます。チャット・メール・ファイルには貼らないでください。
   - ブラウザーが開いたら、ユーザー名 `admin` と決めたパスワードでログインし、マイクの使用を許可します。
4. 画面で次を確かめます。
   - 候補に GPT-Live 1 と Gemini 3.8 Live が選べる。ほかは「（保留）」で選べない。
   - 「この段階の開始：0/2回」と表示される。
   - 「管理画面の設定の反映」が、指示・声とも「接続のときに指定する」になっている。

**手順2：あいさつ、用件、電話番号の復唱と訂正**（台本 C2・C6）

1. 候補を選び、台本のカード C2 を選んで「会話を始める」を押します。
2. 架空の情報で話します：「焼肉ほのか博多店の田中です。無煙ロースター8台の清掃をお願いします。折り返しは090-1234-5678です。」
3. AIが番号を復唱したら、「はい、違います。末尾は5679です」と言います。
4. 確かめること：
   - AIが「はい」を肯定と受け取らず、正しい番号を復唱し直すこと。
   - 「はい、合っています」と言うまで、確認済みにならないこと（画面の記録の「業務処理の結果」）。
   - GPT-Liveでは、**日本語で受付ができるか**を最初に確かめます（公式の言語の一覧がないため）。

**手順3：AIの発話中の「はい」と、「違います」「ちょっと待って」**（台本 C1・C3）

1. AIが話している途中で「はい」と短く言います。AIが止まらずに続けるのが期待どおりです。
2. 次に、AIの発話の途中で「違います」「ちょっと待って」と言います。
3. 判定の欄の「実際に再生が止まった（耳で確認）」と「聞かれていない部分を、伝えた扱いにしていない」を、耳で確かめて記入します。画面の「2.5秒以内」は目安で、合格の基準ではありません。

**手順4：業務処理中の追加・訂正と、発話でのAIの拒否**（台本 C5。各候補の2回目の会話の最後に行う）

1. 台本のカード C5 を選びます（業務処理を4秒遅らせます）。その間に「ダクトの点検もお願いします」と追加します。
2. AIが処理の結果を先に約束しないこと、追加した用件が記録に入ることを確かめます。
3. 最後に「AIは使わないでください」と言います。
   - 画面が、AIへの送信と再生を止めて接続を閉じ、「AIの拒否（発話）」と記録して、状態が「終了」になるのが期待どおりです。
   - この後、その会話では何も業者へ送りません。電話では、この後は録音済みの音声とプッシュボタンで折り返し先を受け付けますが、ブラウザーでは確かめられません。
4. 録音の拒否を試す場合は、「録音はしないでください」と言います。会話は続くのが期待どおりです（AIを拒否していないため）。

**手順5：管理画面で、受付記録と通知のプレビューを確かめる**

1. 会話を終えたら、判定とメモを記入して「結果を保存」を押します。
2. 画面の「管理画面で開く」から受付記録を開き、受付の項目（本人確認済みかどうか）、出来事の記録、通知のプレビューを確かめます。試験の会話では通知は作りません。
3. 管理画面の「費用の台帳」で、その会話の留保が「照合待ち」になっていることを確かめます。後日、業者の利用画面の額を入力して照合します。

**接続の予備試験の回数の使い方（各候補2回）**

| 回 | 行うこと |
| --- | --- |
| 1回目 | 手順2・手順3（つながる・聞こえる・日本語・割り込み・業務処理が届く） |
| 2回目 | 手順3・手順4（処理中の追加と、最後に発話でのAIの拒否） |

動いた候補だけ、詳しい会話比較（C1〜C6、`LAB_STAGE=detailed`）に進みます。

## 2. 何ができるか

- 1つの画面で候補を切り替えて、マイクで実際に話せます。
- 受付業務・FAQ・業務処理（ツール）は全候補で共通です。業務処理は、管理画面と同じ**受付の共通処理**を通ります。
  - FAQ・声・指示は、会話の開始時の管理画面の設定を使います（反映の範囲は6章）。
  - 業務処理は、確認のガードを通ります（復唱の後に、お客様の発話で明確な肯定がない限り確定しない）。
  - お客様の文字起こしは、番号を付けてサーバーへ送ります。確認のガードが返事として使うのは、この文字起こしだけです。業務処理に添えた文字列は使いません。
  - 会話は受付履歴に「ブラウザー会話試験」として残ります。試験の会話では通知は作りません。
- 共通会話の台本C1〜C6のカードを選んでから話すと、記録がその台本に結びつきます。
- 計測は、**この端末の音量だけ**で行います。
  - **応答の遅延**：お客様の発話が終わってから、AIの音が聞こえ始めるまで。
  - **割り込みの結果**：AIの発話中にお客様が話し始めたら、すべてに結果を付けて残します（2.5秒以内に停止〈目安〉／遅い停止／止まらず／判定前に次の発話／会話の終了で未判定）。
  - 端末の音量では、AIが話し終えたのか、遮られたのかを区別できません。そのため、端末の音量だけで復唱を無効にはしません。無効にするのは、業者が割り込みを知らせたときだけです（Geminiの `interrupted`、Cartesiaの `audio_output_clear` など）。GPT-Liveには割り込みの知らせがないので、遮られた復唱を検出できません（制約）。
- 判定の欄は2つに分かれています。
  - **音声**：相づちで不要に止まった、訂正を取りこぼした、停止の求めに応じた、実際に再生が止まった（耳で確認）、聞かれていない部分を伝えた扱いにしていない、自然さ1〜5。
  - **業務処理**：番号・日時の復唱と確認が正しい、受付記録が会話と一致。
- 「AIの拒否（模擬）」：お客様がAIでの処理を拒否した想定で、業者への接続を閉じます。

## 3. 動かし方の補足

- 必要なもの：Python 3.11以上（追加のパッケージは不要）、新しいChromeまたはEdge、ヘッドセット（推奨）。Windowsでの入れ方は [はじめての起動（Windows）](./start-windows.md)。
- マイクは試験をする人のブラウザーにあるため、**試験をする人のPC**で動かします。
- 単独でも動かせます：`python3 -m prototype.browser_lab` で起動し、`http://127.0.0.1:8765` を開きます（ログインなし、自分のPCの中だけ）。管理画面と単独の試験のサーバーを、同じデータベースで同時に動かさないでください。

| 環境変数 | 内容 |
| --- | --- |
| `OPENAI_API_KEY` | GPT-Live 1。OpenAIの試験専用のプロジェクトで作る |
| `GEMINI_API_KEY` | Gemini 3.8 Live。Google AI Studio で作る |
| `GPT_LIVE_DELEGATION_MODEL` | 任意。GPT-Liveの裏方のモデル（既定 `gpt-6-luna`）。単価が登録されたモデルだけ使える。高いモデルにすると、台帳の上限で開始できない |
| `LAB_STAGE` | `connection`（既定。接続の予備試験）か `detailed`（詳しい会話比較） |
| `LAB_RELEASE_HOLD` | 保留の候補を解く（例：`elevenagents`）。利用者の承認の後だけ。回数と台帳の上限も決め直すまでは0回のまま |
| `ELEVENLABS_OVERRIDES` | 保留中。ElevenLabsの画面で上書きを許可した項目（`prompt`、`voice`） |

**安全のための作り**

- サーバーは自分のPCの中（127.0.0.1）だけで待ち受けます。ほかのホスト名や、別のサイトからの要求は断ります。管理画面経由ではログインとCSRFのトークンが要ります。
- 鍵はブラウザーに渡しません。サーバーが業者から短時間だけ使える接続情報を受け取り、その会話の接続のためだけに画面へ渡します。GPT-Liveは、接続の交換そのものをサーバーが行います（1回の会話につき1回だけ）。
- 鍵がない構成と保留の構成は、画面で選べません。何も送りません。

## 4. 開始の回数の数え方

サーバーのデータベースで、候補×段階ごとに数えます。再起動しても、同時に開始しても、数は守られます。超えるなら、業者に何も送らずに断ります。

| 状態 | 数え方 |
| --- | --- |
| 接続情報を発行した会話（失敗・切断・期限切れ・再起動で失われたものを含む） | 1回と数える |
| 接続情報の発行に失敗した会話 | 回数には数えない。ただし候補×段階で2回まで。超えたら、鍵と設定を確かめてから `python3 -m prototype.browser_lab --reset-mint-failures 候補` で人が解除する |
| 起動したときに進行中のまま残っていた会話 | 「再起動で失われた」とし、留保は残す |

## 5. 業者ごとの準備（試験の対象）

**共通**

- 試験専用のプロジェクトや鍵を作り、業者側でも予算と通知を設定します。業者側の予算も、前払いの残高も、上限で必ず止まるとは限りません。
- 指示文は、会話の開始時に管理画面のFAQから作り、サーバーが接続のときに送ります。
- 業務処理（ツール）は次の5つです。定義は `python3 -c "import json; from prototype.reception.tooldefs import RECEPTION_TOOLS; print(json.dumps(RECEPTION_TOOLS, ensure_ascii=False, indent=1))"` で表示できます。

  | ツール | 引数 |
  | --- | --- |
  | `save_field` | `field`, `value` |
  | `request_readback` | `field` |
  | `confirm_field` | `field`, `value` |
  | `lookup_faq` | `question` |
  | `flag_emergency` | `level`, `reason` |

| 構成 | 業者側で行うこと | 業務処理の経路 | 試験での注意 |
| --- | --- | --- | --- |
| GPT-Live 1 | OpenAIの試験用プロジェクトの鍵。会話の設定は、サーバーが接続のときに送る | delegation（Responses）。裏方のモデルに5つのツールを関数として渡し、関数呼び出しは `response.event` でブラウザーに届く。ブラウザーが共通の処理へ送り、`response.item.create`＋`response.create` で返す | 裏方のモデルは別料金（L_live）。声は `audio.output.voice`（既定 marin。日本語に合う声は未確認）。言語の設定欄はなく、指示文で日本語を指定する。発話・割り込みのイベントはない |
| Gemini 3.8 Live | Google AI Studioの鍵。無料枠は入出力がGoogleの改善に使われる条件なので、架空のデータだけで使う。有料枠は前払い | 関数呼び出し（`toolCall`／`toolResponse`） | 履歴はターンごとに課金されるため、履歴を短く保つ設定（contextWindowCompression）を送る。声は `prebuiltVoiceConfig`（既定 Kore。3.8で同じ名前が使えるかは未確認） |

保留の候補（ElevenLabs・Cartesia・GPT-Realtime-2.1）の準備は、保留を解くときに改めて確かめます。ElevenLabs はエージェントと client tools を業者の画面で作り、Cartesia は新しいエージェントのWebSocket（`/v1/agents/websocket`）と Client function を使う構成で書いてあります。

## 6. 管理画面の設定が、どこまで反映されるか

| 候補 | 指示（FAQを含む指示文） | 声 | FAQの答え |
| --- | --- | --- | --- |
| GPT-Live 1・Gemini 3.8 Live（と、保留の GPT-Realtime-2.1） | 接続のときに指定する（公式資料のとおり。実接続では未確認） | 同左 | 業務処理 `lookup_faq` が、会話の開始時の設定から返す（全候補） |
| ElevenAgents（保留） | `ELEVENLABS_OVERRIDES` で許可したときだけ反映。それ以外はエージェントの設定で固定 | 同左 | 同上 |
| Cartesia（保留） | エージェントの設定で固定（この画面からは変えられない） | 同左 | 同上 |

- 会話の開始時の設定を使うので、設定を変えると**次の会話から**反映されます。進行中の会話は変わりません。
- 試験の画面は、会話ごとに「この会話に反映する設定」を表示し、結果のファイルにも残します。
- 管理画面の音声の画面では、エージェントの設定で固定の候補の声は「使う声」にできません（記録としての登録はできます）。

## 7. 終わり方と、保証できないこと

| 業者 | 接続情報の寿命 | 終わり方 | 保証できないこと |
| --- | --- | --- | --- |
| GPT-Live 1 | SDPの交換は1回の会話につき1回だけ（サーバーが行う） | 画面は `session.close` を送り、`session.closed` と最終の使用量を最大5秒待ってから閉じる。最大時間を超えたら、サーバーの見張りがサイドバンドの接続で `session.close` を送る | `session.closed` が届かなければ「終了・使用量は未確認」と記録し、留保を残す（実接続では未確認） |
| Gemini 3.8 Live | 1回だけ使える。1分以内に開始。開始から最大時間＋1分で使えなくなる | 画面が接続を閉じる | サーバーから接続を切る方法はない |
| 共通 | — | 画面は10秒ごとにサーバーへ知らせ、停止の指示で閉じる。画面を閉じたときは終了を送る。サーバーの見張りは最大4分＋30秒で期限切れにし、以降の業務処理を断る | アプリ内の制限（業務処理40回、GPT-Liveの裏方の応答60回、`response.create` 40回）は会話を止める仕組みで、業者の課金の上限ではない |

## 8. 発話での拒否

| お客様の発言 | 動作 |
| --- | --- |
| 「AIは使わないでください」「人と話したいので、AIは使わないでください」 | AIの拒否。AIへの送信・再生・業務処理を止め、接続を閉じる。拒否より前の文字起こしは削除する。以降の文字起こしは保存しない |
| 「録音はしないでください」 | 録音の拒否。録音を止め、拒否より前の録音を削除する。AIを拒否していなければ、会話は続ける（折り返し先などの受付の項目は、文字の記録として残る） |
| 「人と話したい」だけ | 拒否ではない。担当者へはつなげないことを説明し、折り返しのためにAIで短く伺ってよいかを一度だけ確認する |
| 「AIは嫌ではありません」「AIでも大丈夫です」 | 拒否ではない |

- 判定は、管理画面の着信テストと同じ共通の処理で行います。
- AIが拒否を認識するまでに業者へ送った音声は、取り消せません。
- 電話では、AIを拒否された後、録音済みの音声とプッシュボタンで折り返し先を受け付けます。この流れは電話の経路でしか確かめられません。

## 9. 結果と記録

- 終わったら「終える」を押し、判定の欄とメモを記入して、「結果を保存」を押します。保存は1回の会話につき1回です。
- 結果は `prototype/results/browser-lab/` に保存されます（gitの対象外）。業者の記録（文字起こし・イベント）、端末の計測、判定、サーバーが記録した業務処理と受付の項目・要約、サーバー側の会話の記録（止めた理由、業者の終了の確認）が入ります。
- AIの拒否の後は、拒否より前の文字起こしを結果から除きます（サーバーでも削除）。

## 10. 費用の管理

- **始める前**：台帳に「最大4分 × その構成の上限の分単価」を留保します（GPT-Liveは、裏方のモデルの厳しめの仮定を足す）。段階ごとの上限を超えるなら、始めません。
- **終えたとき**：時間（課金単位に切り上げ）× 上限の分単価を**推定**として記録します。時間は、画面が知らせた時間と、サーバーが見た接続の時間の長い方です。**留保は閉じません**（照合待ち）。
- **照合**：試験の後、業者の利用画面でその会話の額を確かめ、管理画面の「費用の台帳」で入力します。照合すると、その会話の合計が利用画面の額になり、留保が閉じます。同じ照合を二度しても増えず、違う額での照合し直しは断ります。コマンドでもできます。

  ```bash
  python3 -m prototype.engines.budget                     # 累計・照合待ちの留保
  python3 -m prototype.engines.budget --close <留保ID> --vendor openai_lab --actual-usd 0.21 --note "利用画面で確認"
  ```

- 台帳は、こちら側の見積もりです。業者側の課金の上限を保証するものではありません。使用量が報告されなかった会話を、0円とは扱いません。

## 11. 接続の確認状況
