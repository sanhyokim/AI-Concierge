# ブラウザー会話試験の準備

- 日付：2026年10月5日
- 位置づけ：[仕様書](./spec-draft-v1.md) 5章の**段階2a（ブラウザーでの会話試験）**の道具と手順です。試験の件数と予算案は[実測計画 v2](./measurement-plan-v2.md)にあります。
- 状態：画面・計測・業務処理・費用の留保は、オフラインの模擬と自動試験で動作を確かめました。**業者への接続は、公式資料に沿って書いたもので、実際のアカウントではまだ確かめていません。**
- 範囲外：新しい有料契約、有料APIの実行、本番番号の変更。

---

## 1. 何ができるか

- 1つの画面で候補を切り替えて、マイクで実際に話せます。受付業務・模擬FAQ・業務処理（ツール）は全候補で共通です。
- 共通会話の台本C1〜C6のカードを選んでから話すと、記録がその台本に結びつきます。
- 計測は、**この端末の音量だけ**で行います。マイクの音と、AIの再生音を別々に測るので、業者のイベントの違いに左右されません。
  - 応答の遅延：お客様の発話が終わってから、AIの音が聞こえ始めるまで。
  - 割り込みで止まるまで：AIの発話中にお客様が話し始めてから、AIの音が止まるまで（2.5秒以内に止まったものだけ）。
  - 相づちで停止の可能性：短い発話（0.6秒未満）の後にAIが止まったもの。自動の推定なので、判定の欄の記入を正とします。
- 試験者の判定（相づちで不要に止まった、訂正を取りこぼした、停止の求めに応じた、受付情報が正しく残った、自然さ1〜5）とメモを、結果と一緒に保存します。
- 業務処理は、既存の確認のガード（復唱の後の明確な肯定がない限り確定しない）を通ります。C5を選んでいる間は、業務処理を4秒遅らせます。
- 1回の会話は最大4分で、自動的に切れます。

## 2. 動かし方（試験をする人のPC）

マイクは試験をする人のブラウザーにあるため、このクラウドの環境ではなく、**試験をする人のPC**で動かします。

**必要なもの**
- Python 3.11以上（追加のパッケージは不要）
- 新しいChromeまたはEdge
- ヘッドセット（推奨）。スピーカーで試す場合は、その条件を画面で選んで記録します。

**手順**
1. リポジトリを取得します（ブランチ `claude/new-session-w4sjel`）。
2. 使う構成の鍵を、**そのPCの環境変数**に設定します。鍵はチャットに貼らないでください。ファイルに書く場合も、リポジトリに入れないでください。

   | 構成 | 環境変数 |
   | --- | --- |
   | GPT-Live 1、GPT-Realtime-2.1 | `OPENAI_API_KEY` |
   | Gemini 3.8 Live | `GEMINI_API_KEY` |
   | ElevenAgents | `ELEVENLABS_API_KEY`、`ELEVENLABS_AGENT_ID` |
   | Cartesia Managed Agents | `CARTESIA_API_KEY`、`CARTESIA_AGENT_ID` |

3. 起動します。

   ```bash
   python3 -m prototype.browser_lab
   ```

4. ブラウザーで `http://127.0.0.1:8765` を開きます。マイクの使用を許可します。

**安全のための作り**
- サーバーは自分のPCの中（127.0.0.1）だけで待ち受け、ほかのホスト名からの要求は断ります。
- 鍵はブラウザーに渡しません。サーバーが業者から**短時間だけ使える接続情報**（一時トークン、署名付きURLなど）を受け取り、それだけを画面に渡します。GPT-Liveは、接続の交換そのものをサーバーが行います。
- 鍵が設定されていない構成は、画面で選べません。何も送りません。

**オフラインでの確認**
- 「オフラインの模擬」を選ぶと、業者に接続せずに、画面・計測・保存の流れを確かめられます。音はトーンで、何の声の評価にもなりません。

## 3. 業者ごとの準備

**共通**
- できるだけ試験専用のプロジェクトや鍵を作り、業者側でも予算と通知を設定します。業者側の予算が、上限で必ず止まるとは限りません。
- 新しいアカウントを作る場合は、新しい契約にあたります。作るかどうかを判断してください。
- 指示文と最初のあいさつは、次のコマンドで表示できます。業者の画面に設定するときは、これを貼り付けます。

  ```bash
  python3 -c "from prototype.browser_lab.config import GREETING, LAB_INSTRUCTIONS; print(GREETING); print(); print(LAB_INSTRUCTIONS)"
  ```

| 構成 | 業者側で行うこと | 試験での注意 |
| --- | --- | --- |
| GPT-Live 1 | OpenAIの試験用プロジェクトの鍵。会話の設定は、サーバーが接続のときに送る | 業務処理の受け渡し（delegation）は、仕様の確認待ちで、まだつないでいない。C2・C5の受付情報は、会話の記録で確かめる |
| GPT-Realtime-2.1（基準） | 同上。声は `marin` | 業務処理はつないである |
| Gemini 3.8 Live | Google AI Studioの鍵。無料枠でのデータの扱いを規約で確かめ、必要なら有料の枠を使う | 業務処理はつないである |
| ElevenAgents | ElevenLabsの画面でエージェントを作る：言語は日本語、Expressive mode、日本語の声、使うLLM（記録しておく）、指示文、最初のあいさつ。client tools として `save_field`・`request_readback`・`confirm_field`（引数は `field` と `value`、応答を待つ）を登録する。割り込みのクライアントイベントを有効にする。エージェントを非公開にし、署名付きURLで接続する | 実際に選べるモデル・声・地域を記録する。最新の単体の音声合成モデルが、Agentsで選べるとは限らない |
| Cartesia Managed Agents | Cartesiaの画面でエージェントを作る：音声認識はInk-2（日本語）、音声合成はSonic-3.6（日本語の声）、使うLLM（記録しておく）、指示文、最初のあいさつ | 業務処理はCartesia側で動く前提で、ブラウザーには届かない。出力音声の形式は入力（16kHzのPCM）と同じと仮定しており、未確認 |

## 4. 試験の進め方

1. 候補と条件（ヘッドセット／スピーカー、エコー抑制、試験の回）を選び、「会話を始める」を押します。
2. 台本のカードを選び、カードに書いたとおりに話します。架空の情報だけを使います（[実測計画 v2](./measurement-plan-v2.md) 3章の試験用の情報）。
3. 終わったら「終える」を押し、判定の欄とメモを記入して「結果を保存」を押します。
4. 結果は `prototype/results/browser-lab/` に保存されます（gitの対象外）。業者の記録（文字起こし・イベント）・業務処理の記録・端末の計測・判定が入ります。

## 5. 費用の管理

- 会話を始める前に、台帳に「最大4分 × その構成の上限の分単価」を留保します。上限を超えるなら、始めずに止まります。
- 終えたときに、計った時間（業者の課金単位に切り上げ）× 上限の分単価を**推定**として記録し、留保を閉じます。終えずに画面を閉じた会話は、留保したまま残ります。
- 試験の後、業者の利用画面の額で照合します。照合すると、その会話の合計が利用画面の額になります。同じ照合を二度しても、増えません。

  ```bash
  python3 -m prototype.engines.budget                     # 累計・開いたままの留保
  python3 -m prototype.engines.budget --close <留保ID> --vendor openai_lab --actual-usd 0.21 --note "利用画面で確認"
  ```

- 台帳は、こちら側の見積もりです。業者側の課金の上限を保証するものではありません。
