# 最小の実測計画 v1

- 日付：2026年10月4日
- 目的：4候補（案Aの`marin`・`cedar`、案Bの`Kazuha-Neural`・`Takumi-Neural`）を比べるのに欠かせない計測を、できるだけ少ない回数と費用で行う。
- 範囲外：**新しい有料契約と、本番番号の設定変更**。Twilioの電話経路も、契約が要るので今回は行いません。
- 費用の見込みは `python3 -m prototype.cost.measurement_budget` で作り直せます。単価は[費用比較表](./cost-comparison-v1.md)と同じ `prototype/cost/prices.json` を使います。

## 1. 結果の経路を分ける

結果のファイルと利用量の台帳には、必ず `path` 欄を付けます。経路の違う結果は、同じ表の同じ行にまとめません。

| `path` の値 | 中身 | この計画での試験 |
| --- | --- | --- |
| `openai_api_direct` | OpenAIのAPIを直接呼ぶ。電話網は通らない | T1、T3 |
| `polly_direct` | Pollyを直接呼ぶ。**ConversationRelayも電話網も通らない** | T2（と、T3の発信者音声） |
| `relay_phone` | Twilio ConversationRelay・電話経由 | 今回は行わない（Twilioを使うかの判断の後） |
| `public_human_recording` | 公開されている人の朗読（電話の符号化だけ模擬） | T4（[実音声での予備確認](./realvoice-method-check-v1.md)） |

- `polly_direct` の結果は、Relay経由で同じように動くことの証明になりません。
- Pollyの試験費用は**案Bの一部**の費用です。案B全体（Relay・電話経路・会話モデル）の費用ではありません。

## 2. アカウントと認証情報

### 2-1. 前提

- **今あるアカウントで行えるものだけ**を行います。OpenAIのAPIやAWSのアカウントを新しく作る必要があるなら、それは新しい契約にあたるので、実施するかをユーザーが判断してください。
- 試験で送るのは、架空の店名・人名・電話番号を使った台本だけです。実際のお客様の情報は送りません。
- 認証情報は、**チャットに貼らないでください**。環境の設定に登録します（2-4）。
- このセッションの環境にあるほかのAWSの認証情報は使いません（自動の権限判定でも止められています）。専用の変数名だけを読みます。

### 2-2. OpenAI（案A：T1、T3）

1. 今ある組織に、試験専用のプロジェクトを作ります（例：`concierge-measurement`）。
2. そのプロジェクトに、予算と通知を設定します。
   - 予算：$15。通知：50%と80%。
   - 予算の設定は、上限で必ず止まる仕組みとは限りません。このため、こちらの実行側でも止めます（4章）。
3. そのプロジェクトの中で、鍵を作ります。
   - 権限は「制限付き」にし、Realtime（音声の会話と文字起こし）に要るものだけを許可します。権限の名前は管理画面の表示に従ってください。
   - 試験が終わったら、鍵を無効にします。
4. 登録する変数：`OPENAI_API_KEY`

### 2-3. AWS（案Bの一部：T2。T3の発信者音声）

1. 試験専用のIAMユーザーを作ります（例：`concierge-polly-test`）。管理画面へのログインは不要です。
2. 次のポリシーだけを付けます。音声の合成と、声の一覧の取得だけを許可し、東京リージョンに限ります。

   ```json
   {
     "Version": "2012-10-17",
     "Statement": [
       {
         "Sid": "PollySynthesizeOnly",
         "Effect": "Allow",
         "Action": ["polly:SynthesizeSpeech", "polly:DescribeVoices"],
         "Resource": "*",
         "Condition": {"StringEquals": {"aws:RequestedRegion": "ap-northeast-1"}}
       }
     ]
   }
   ```

3. そのユーザーのアクセスキーを作ります。試験が終わったら、無効にして削除します。
4. AWS Budgetsで、月の費用の予算（$2）と通知を設定します。これも上限で止まる仕組みではないので、実行側でも止めます。
5. 登録する変数：`CONCIERGE_POLLY_ACCESS_KEY_ID`、`CONCIERGE_POLLY_SECRET_ACCESS_KEY`、`CONCIERGE_POLLY_REGION`（`ap-northeast-1`）

### 2-4. 環境への登録

- 場所：セッションのタイトルバーにあるクラウド環境のメニュー → Edit。
  - 「API credentials」の欄があればそこへ、なければ環境変数として、上の変数名で登録します。
- 登録した値は、**新しいセッションから**読み込まれます。
- 登録の後、`pip install -r prototype/requirements-vendor.txt` を実行します。
- 変数がないときは、どのスクリプトも外部へ何も送らずに終わります（試験で確認済み）。

### 2-5. Twilio（今回は行わない）

- 無料トライアルでは `<ConversationRelay>`・`<Stream>`・`<Record>` が使えません。電話経路の試験には有料のアカウントが要ります。
- このため、`relay_phone` の計測は、Twilioを使うかを判断した後に回します。

## 3. 試験の内容と件数

| 記号 | 試験 | 件数 | 経路 | コマンド |
| --- | --- | --- | --- | --- |
| T1 | 案Aの部分減速（N版とD版） | 2声 × S台本3件 × N/D × 方法2つ（`split`・`instr`） × 2回 ＝ **48回の生成**（応答は96回。`split`は1回の生成に3応答） | `openai_api_direct` | `python3 -m prototype.engines.realtime_probe` |
| T2 | 案Bの部分減速（Polly直接） | 2声 × S台本3件 × （N版 ＋ D版80% ＋ D版70%） ＝ **18回の生成**（音声とスピーチマークで**36回の要求**） | `polly_direct` | `python3 -m prototype.engines.polly_probe` |
| T3 | 案Aの対話 | 7シナリオ（C-01、C-04、I-02、I-03、R-03、X-02、X-02b） × 2声 × 3回 ＝ **42回** | `openai_api_direct` | 下の手順 |
| T4 | 実音声での計測方法の確認 | 済み（業者の費用なし）。人のラベルでの比べ直しが残る | `public_human_recording` | `python3 -m prototype.realvoice.compare --labels human-verified` |
| T5 | 試聴 | 3名以上。T1とT2の音声（N版とD版）を、順番を入れ替えて聴く | T1・T2と同じ | 業者の費用なし |

**T3の手順**
1. 発信者の音声を作ります。候補ではない声（Polly `Mizuki`、Standard）で、16ターン分を作ります。作ったものは再利用し、2回目からは何も送りません。

   ```bash
   python3 -m prototype.engines.make_caller_audio
   ```

2. 対話を1件だけ流し、1件あたりの費用が見込み（約$0.11）の2倍を超えないことを確かめます。

   ```bash
   python3 -m prototype.engines.run_dialog --scenario R-03 --voice marin
   ```

3. 問題がなければ、残りを流します（同時には動かさず、1件ずつ）。

   ```bash
   for s in C-01 C-04 I-02 I-03 R-03 X-02 X-02b; do
     for v in marin cedar; do
       for r in 1 2 3; do
         python3 -m prototype.engines.run_dialog --scenario "$s" --voice "$v" || exit 1
       done
     done
   done
   ```

   1回目の手順2の1件も、3回のうちの1回として数えます（ループでは、その分を1回減らして構いません）。

**T3で測るもの**
- 割り込みで止まるまでの時間、応答の遅延（測る地点はAPI側で、電話網は含まない）
- 保存した値と確認の状態（R-03の「はい、合っています」の前に確定しないこと）
- 関数呼び出し、AIの音声

**T2で追加して確かめること**
- スピーチマークの境界と、ツールが見つけた間の端のずれ。30msを超えるなら、境界を近くの間に寄せる処理を加えてから測り直します（[実音声での予備確認](./realvoice-method-check-v1.md) 3-3）。

## 4. 実行側の制限

業者側の予算や通知とは別に、実行するスクリプトの側でも止めます（`prototype/engines/budget.py`）。

**上限**（計画の件数の約2倍＝全体を1回やり直せる分）

| 業者 | 要求の回数 | 音声の秒数 | 見込み額（USD、税抜） |
| --- | --- | --- | --- |
| OpenAI | 700回 | 3,600秒 | $15 |
| AWS Polly | 120回 | 600秒 | $2 |

**動き**
- 要求を送る**前に**、台帳の累計と次の要求の見込み額を足し、上限を超えるなら送らずに止めます（`BudgetExceeded`）。
  - OpenAIは、1応答を悲観的に見積もります（30秒の音声出力と、キャッシュされない2万トークンの入力）。T1は応答ごとに、T3はお客様役の発話ごとに3応答分で確かめます（関数呼び出しの後の応答も含めるため）。T3では、接続する前にも1回確かめます。
  - Pollyは、送る文字数で見積もります。
- 上限は、台帳の累計で数えます。スクリプトを分けて実行しても、合計で効きます。
- 時間の上限：1回の要求は60秒、1回の対話は180秒。超えたら打ち切ります（対話の結果には `timed_out` と書きます）。予算で止まった対話は、結果に `stopped_by_budget` と書きます。
- 再試行：ネットワークの失敗・時間切れ・5xxだけ、**最大1回**。4xxは再試行しません。
- 同時に動かすのは1本だけです（スクリプトは順番に処理します）。

**利用量の台帳**
- 場所：`prototype/results/usage-ledger.jsonl`（1行に1要求）
- 書く項目：時刻、業者、操作、経路（`path`）、実行ID、音声の秒数、見込み額、単位の内訳（OpenAIは`response.done`のトークンの内訳、Pollyは課金された文字数）
- 累計の確かめ方：

  ```bash
  python3 -c "from prototype.engines.budget import UsageLedger as L; print(L('openai').totals(), L('aws_polly').totals())"
  ```

- 新しい期間として数え直すときは、台帳を消さずに別名へ移します。
- 台帳に入らないもの：案Aの入力の文字起こし（`gpt-4o-transcribe`）。使用量は`response.done`に含まれないためです。量は発信者の音声で合計7分程度ですが、単価は未確認（費用比較表のV_asr）なので、業者の利用画面で確かめます。

## 5. 費用の見込みと推奨予算

| 試験 | 業者 | 要求の回数 | 見込み額（USD、税抜） | 主な仮定 |
| --- | --- | --- | --- | --- |
| T1 | OpenAI | 96 | 約$1.2 | 1回の読み上げは11秒。指示文はキャッシュされない1,000トークン（悲観的） |
| T3 | OpenAI | 約210 | 約$4.8（1件あたり約$0.11） | 1件で応答5回、AIの音声25秒、音声の履歴2,000トークン（キャッシュなしとして計算） |
| T2 | AWS Polly | 36 | 約$0.10 | 1回の要求は170文字（SSMLのタグを含めた上限） |
| T3の発信者音声 | AWS Polly | 16 | 約$0.001 | 350文字（Standard） |
| **合計** | | | **約$6.1** | |

**推奨予算**
- OpenAI：$15（業者側の予算と、実行側の上限の両方）
- AWS：$2（同上）
- 合計で$20以内（税別）。見込みの約3倍で、全体を1回やり直しても収まります。
- 税：OpenAIとAWSの消費税の扱いは未確認です。安全側に、10%を加えた額を見ておきます。
- Pollyの新規アカウント向けの無料枠は、使える場合でも見込みには入れていません。

## 6. 実行の順番と、止める条件

| 順 | 内容 | 次へ進む条件 |
| --- | --- | --- |
| 1 | T2（Polly直接）。費用が最も小さく、認証情報とスピーチマークの確認になる | 36回の要求がすべて成功し、台帳の額が見込みの2倍以内 |
| 2 | T1（OpenAI。部分減速） | 48回の生成が済み、`split`の自動計測が出る。`instr`は区間のラベルを人が付ける |
| 3 | T5（試聴。3名以上） | T1とT2の音声がそろっている |
| 4 | T3（発信者音声 → 対話1件 → 残り） | 1件目の費用が見込みの2倍以内 |

**止める条件**（どれか1つで止め、原因を報告します）
- `BudgetExceeded` が出た。
- 4xxのエラーが出た（権限・鍵・要求の形の問題で、再試行しても直らない）。
- 1件の費用が、見込みの2倍を超えた。見込みを作り直してから再開を判断します。
- 結果の `path` が、想定した経路と違う。

## 7. 報告の形

- 経路ごとに別の表にします（`openai_api_direct`、`polly_direct`、`public_human_recording`）。
- 台帳の累計と、業者の管理画面の利用額を並べ、差があれば理由を書きます。
- 合否は「提案目標（未合意）」に対する結果として書き、合意値の欄は空けておきます（[仕様書ドラフト](./spec-draft-v1.md) 5-3）。
- 試験の件数と誤りの件数をそのまま書きます。「試験で0件」を「本番でゼロ」とは書きません。
