## 1. 目的と使い方

案A（OpenAI Realtime）と案B（ConversationRelay）を、**同じ台本・同じテスト番号・同じ測定地点**で評価します。そのための台本です。

**発信者の役**
- 合成発信者を使います。候補とは別の音声合成で、台本どおりのタイミングで話します。
- 人が台本を読むこともあります。人が読むのは、自然さの評価と、端末側（T）での測定のときです。

**経路**
- 試験用の番号から、テスト番号へ実際に電話をかけます。
- 実回線（0120、092）は使いません。実回線は、実回線試験の作業枠（設計レビュー5-4）で別に扱います。

**測定地点**
- **S（クラウド側）**：Twilioの2チャネル録音と、イベントの時刻から測ります。全件で測ります。
- **T（端末側）**：発信者の端末で、受話の音声と自分の発話を同時に録音して測ります。代表的な条件（携帯電話・固定電話）で、30ターン以上測ります。
- SとTの差を報告します。TをSで代用しません。

**模擬データ**
- 店名・人名・電話番号はすべて架空です。電話番号は台本で読み上げるだけで、**実際には発信しません**。
- FAQは、野田のダクト清掃ページの掲載内容を**模擬FAQ（未承認）**として使います。
- 本番では、管理者が承認したFAQに置き換えます。

## 2. 試験結果の扱い

- 結果は「試験n件中、誤りk件」と、事実として報告します。
- 手作りのシナリオは独立でなく、本番の通話の分布とも違います。このため、試験で誤りが0件でも、本番の誤り率の上限を保証するものとしては扱いません（設計レビュー3-3）。
- 判定は「合格」「不合格」「要確認」の3つです。人による聴取が必要なものは「要確認」とし、聴取した後に合格か不合格かを決めます。

## 3. 台本の書式

| 項目 | 内容 |
| --- | --- |
| ID | 区分の記号と番号（例：C-01） |
| 必須条件 | 設計レビュー3-1の5項目（継続的な会話／部分的な減速／複数の声／割り込み／聞き取りと復唱）、または緊急・拒否・FAQ |
| 前提 | 通話の開始時刻（日本時間）、回線から取れる発信者番号、同意の状態など |
| 発信者 | せりふの要旨。→ でターンを区切る。〔 〕はタイミングの指示 |
| 期待する動作 | 文言は固定しない。何をするか、何をしないかを書く |
| 合格の判断 | 自動で確認できる条件と、聴取で確認する条件 |

**タイミングの指示の書き方**
- 〔AI発話中+0.8秒〕：AIが話し始めてから0.8秒後に話し出す
- 〔AI発話終了+0.3秒〕：AIが話し終えてから0.3秒後に話し出す
- 〔無言10秒〕：10秒間何も話さない
- 〔雑音：厨房〕：換気扇や調理の音を混ぜる

**共通の模擬データ**

| 種類 | 値（すべて架空） |
| --- | --- |
| 店舗 | 焼肉ほのか 博多店、炭火焼き鳥 とり吉、焼きとん まるや 天神店 |
| 人名 | 田中、山口、松尾 |
| 携帯番号 | 090-1234-5678、080-2345-6789 |
| 固定番号 | 092-123-4567 |
| 模擬の通話時刻 | 2026-10-05（月）10:00、2026-10-06（火）0:30。2026-10-12（月）はスポーツの日（祝日） |

### S：部分的な減速（台本3件 × 各候補の音声）

同じ文章を、**同じ声で**2通りに読ませて比べます（v1.1）。

- **通常版（N）**：全体を通常の速さで読む。
- **減速版（D）**：〔減速〕〜〔/減速〕の区間（番号・日時・金額）だけ遅くし、その後は通常の速さに戻す。

候補ごとの実現手段は、[対応表](./voice-candidates-v1.md)の「部分減速の手段」の列に従います。

| ID | 読み上げる文章（〔減速〕〜〔/減速〕が対象の区間。N版では印を無視して通常の速さで読む） |
| --- | --- |
| S-01 | ありがとうございます。お電話番号を確認します。〔減速〕ゼロキュウゼロ、イチニーサンヨン、ゴーロクナナハチ〔/減速〕。こちらでお間違いないでしょうか。 |
| S-02 | ご希望の日時を確認します。〔減速〕10月6日、火曜日の、午後2時〔/減速〕。担当者から改めてご連絡いたします。 |
| S-03 | 無煙ロースターの清掃は、〔減速〕1台あたり2万5千円から3万5千円、税別〔/減速〕が目安です。正式な金額は、無料の現地調査のあとにお見積もりします。 |

**区間の分け方**
- 文章を3つの区間に分けます：前（対象の直前の通常区間）・対象・後（対象の直後の通常区間）。
- 区間の境界は、次の方法で決めます。
  - Polly：SSMLの`<mark>`で得るスピーチマーク
  - 案Aの「応答を分ける方法」：応答の切れ目
  - 案Aの「指示文の方法」：手作業でラベルを付けたファイル

**測るもの**（N版とD版のそれぞれで、区間ごとに、分けて測ります）
- **発音速度**：モーラ数 ÷（区間の長さ − 間の合計）。単位はモーラ/秒。モーラ数は読みのカナから数えます。
- **区切りの間**：150ms以上続く無音の、個数と合計時間。閾値を100msと200msにした場合の値もあわせて報告します。
- **全体の話速**：モーラ数 ÷ 区間の長さ（間を含む）

**比べるもの**
- 発音速度比 ＝ D版の対象区間の発音速度 ÷ N版の対象区間の発音速度
- 間の増え方 ＝ D版の対象区間の間の合計 − N版の対象区間の間の合計（参考として報告）
- 通常の速さへの戻り ＝ D版の「後」区間の発音速度 ÷ N版の「後」区間の発音速度
- 聴取評価：3名以上で、N版とD版を聴き比べます。評価するのは「聞き取りやすさ」と「不自然な途切れや声の変化がないか」です。

**合格の判断（提案）**
- 発音速度比が0.85以下（仮）
  - **区切りの間が増えただけで、発音速度が落ちていない場合は合格にしません。**
- 通常の速さへの戻りが0.95以上
- 聴取評価で、D版の対象区間を「聞き取りやすい」とした人が過半数
- 聴取評価で、「声が変わった・途切れた」とした人が過半数ではない

**注意**
- 数字をカナにしたことは、それだけでは合格の理由にしません。モーラ数は、N版とD版で同じ読みから数えるので、比の計算には数え方の誤差の影響が出ません。

**記録すること**
- 候補ごとに、使った手段を記録します。
  - 案A：指示文か、応答を分ける方法か
  - 案B：Polly・GoogleのSSML
  - ElevenLabs（E1）：比較のため、全体の話速の設定だけで流した結果

### V：複数の声（試聴の台本）

すべての候補を、**電話経路を通して**同じ文章で比べます。対象は[対応表](./voice-candidates-v1.md)で「Relayで使える」または「案A」とした候補で、G6は除きます。

> お電話ありがとうございます。株式会社野田、AI受付です。ご用件を担当者にお伝えし、折り返しご連絡いたします。お電話番号は、ゼロキュウニー、イチニーサン、ヨンゴーロクナナ、でよろしいでしょうか。ご希望は、10月6日、火曜日の、午後2時ですね。無煙ロースターの清掃は、1台あたり2万5千円から3万5千円、税別が目安です。申し訳ございませんが、正式な金額は、現地調査のあとのお見積もりとなります。もし今、炎や、いつもと違う煙・焦げ臭さがある場合は、すぐに119番へ通報してください。

**評価の項目**（5段階。3名以上、各候補とも同じ順番の影響が出ないよう順番を入れ替える）
- 明瞭さ
- 自然さ
- 敬語の自然さ
- 番号の聞き取りやすさ
- 印象：「はきはき」「穏やか」のどちらに近いか

**合格の判断（提案）**
- 「明瞭な女性系」「穏やかな男性系」のそれぞれで、平均4.0以上（仮）の候補が1つ以上ある
- 公開する声はすべて、電話経路での確認が済んでいる

## 5. 記録する項目と採点の手順

**通話ごとに記録すること**
- 台本のID、候補（案・音声ID・手段）、測定地点（S／T）、実行日時
- 録音（2チャネル）とイベントの時刻（発話の開始と終了、AIの発話の開始と終了、割り込み、切り詰め）
- 保存された受付の記録（7章の形式）と、期待値との差
- 指標（設計レビュー3-2）：応答遅延、割り込みの停止、誤停止、誤確定、減速比、緊急の分類、案内までの時間

**採点の手順**
1. 自動で照合する。保存値・状態・分類・同意の状態を、期待値と比べる。
2. 自動で計算する。遅延・停止時間・話速の比などを録音から求める。
3. 人が聴取する。自然さ、部分減速、声の印象、断定の有無を確かめる。
4. 判定する。合格／不合格／要確認とし、要確認は聴取の後に確定する。
5. 集計する。区分ごと・候補ごとに「n件中の合格数」と指標の分布（中央値、p90、最大値）を出す。

## 8. 規定数まで増やす方針と、次の版で決めること

**件数を増やす方針**
- 設計レビューの規定数に届かない区分は、同じ意図の言い換えで増やします。
  - 緊急：危険20件以上、紛らわしい非危険30件以上、曖昧10件以上
  - 誤確定：番号と日時でそれぞれ50件以上
- 言い換えの元になる台本のIDを記録します。
- 方言（博多弁など）、早口、高齢の話者、厨房の雑音の強弱を、条件として組み合わせます。

**次の版で決めること**
- 合成発信者の作り方（使う音声合成、雑音の混ぜ方、タイミングを制御する方法）
- 端末側（T）で測るときの機材と手順
- 聴取評価をする人の選び方と人数
- 模擬FAQを、承認済みのFAQに置き換える時期（回線の契約情報を受け取った後、検証計画を具体化するときに決める）
