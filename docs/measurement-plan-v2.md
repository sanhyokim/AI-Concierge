## 2. 共通会話（C1〜C6）

評価台本のC-01〜とは別の記号です。

| ID | お客様役の操作・発話 | 確かめること |
| --- | --- | --- |
| C1 | AIの発話中に「はい」「うん」と短く相づちする | 不必要に止まらない。次の必要な内容を自然に話す |
| C2 | 同じ位置で「はい、違います。電話番号は…」と訂正する | 冒頭の「はい」だけを肯定にしない。訂正を聞き、正しい番号を復唱し、肯定を得るまで確認済みにしない |
| C3 | AIの発話の最初・途中・終わり際で「ちょっと待って」と言う | 止まって待つ。言い終えていない部分を、伝えた扱いにしない |
| C4 | 考えて一度間を空け、同じ発話を言い直す | 発話の終わりを早まって決めない。言い直した後の意味で受け付ける |
| C5 | 業務処理を遅らせ（4秒）、その間に用件を追加・訂正する | 処理中も聞ける。結果を先に約束しない。保存・要約と会話が食い違わない |
| C6 | 株式会社野田、ダクト、無煙ロースター、電話番号、日付・時間を伝える | 発音と受付の正確さ。電話番号・日時を区切って明瞭に復唱し、確認する（部分減速は必須ではない） |

- 続いて、AIの拒否・録音の拒否・緊急の案内・接続の障害・通知の既存のシナリオを行います。優先順位を変えたことを理由に、既存の機能・同意・確認の条件は削りません。
  - 発話でのAIの拒否（「AIは使わないでください」）は、AIへの送信・再生・業務処理を止め、接続を閉じます。
  - 発話での録音の拒否（「録音はしないでください」）は、録音を止めて拒否より前の録音を削除しますが、AIを拒否していなければ会話は続けます。
- 少数の試験は、条件に合わないものを見つけるための試験です。誤りが0件でも、合格基準を達成した証拠や、本番の誤り率の保証にはしません。

## 3. 試験の条件

- 同じPC・同じマイク・同じヘッドセット・同じ回線で比べます。スピーカーで試す場合は、その条件を記録し、ヘッドセットの結果とは分けます。
- エコー抑制はオンにします（AI自身の声を、お客様の割り込みと誤って取らないため）。
- 架空の情報だけを使います。

| 項目 | 試験用の値（架空） |
| --- | --- |
| 店名・名前 | 焼肉ほのか博多店、田中 |
| 折り返し先 | 090-1234-5678（C2では、5679に訂正する） |
| 希望日時 | 10月8日（木）の午後3時（C2・C6で「9日の金曜」に変える） |
| 用件 | 無煙ロースター8台の清掃。C5で「ダクトの点検も」を追加する |

## 4. 記録すること

| 項目 | 取り方 |
| --- | --- |
| お客様が割り込み始めてから、端末でAIの音が止まるまで | 画面の計測（端末の音量） |
| 発話の終わりから、端末で次のAIの音が聞こえるまで | 同上 |
| 相づちでの不要な停止と、訂正の取りこぼし | 別々に記録する。試験者の判定を正とし、自動の推定は参考 |
| 割り込みごとの結果 | すべての割り込みに結果を付けて残す：2.5秒以内に停止（目安。合格の基準ではない）／遅い停止（2.5〜6秒、時間も記録）／止まらず（6秒以内に停止なし。短い相づちかを区別）／判定前に次の発話／会話の終了で未判定。停止の中央値・p90は測れたものだけで出し、測れなかった件数を並べて示す。良い値だけを集計しない |
| 重なった発話の内容、訂正の後に保存された番号・用件 | 業者の文字起こしと、サーバーの業務処理の記録 |
| サーバーが送った音声と、端末で実際に再生された範囲 | 端末の再生は音量で記録。業者のイベントは記録に残す。両者を同じものとはみなさない。端末の音量では、AIが話し終えたのか遮られたのかを区別できない |
| 実際に再生が止まったか、聞かれていない部分を伝えた扱いにしていないか | 試験者が耳で判定し、判定の欄に記入する |
| 業者が知らせた割り込み | Geminiの `interrupted`、Cartesiaの `audio_output_clear`・`turn_ended.interrupted` など。サーバーに送り、返事の前に遮られた復唱を確認済みにしない。GPT-Liveには割り込みの通知がないので、遮られた復唱を検出できない（制約） |
| 構成・版・声・接続方式・設定・回数・時間・費用 | 結果のファイルと台帳 |
| 実装による遅延と、モデル側の遅延 | できる範囲で分ける（業者のイベントの時刻と、端末の音の時刻の差） |

相づちを区別できない候補は、ほかが得意でも、上位の会話条件を満たしません。同時発話の機能の説明が薄い候補も、実測で条件を満たすことはあるので、機能の名前だけで順位を付けません。

## 6. 実行側の制限と台帳

- **開始の回数**：候補×段階ごとに、サーバーのデータベース（`lab_sessions`）で、ひとつのトランザクションの中で数えます。超えるなら、業者に何も送らずに断ります。再起動しても、同時に開始しても、数は守られます。
  - 接続情報を発行した会話は、失敗・切断・期限切れ・再起動で失われたものも含めて1回と数えます。
  - 接続情報の発行に失敗した会話と、業者が接続を拒否した会話（HTTP 4xx。業者の会話は作られていない）は数えません。ただし、合わせて候補×段階で2回までです。超えたら、原因を確かめてから、人が管理画面の「費用の台帳」で解除します。
  - GPT-Liveで、OpenAIへ何も送る前に画面で失敗した会話（マイク・ネットワークの準備など）は数えません。
  - 通信の失敗や業者の5xxなど、業者の会話が作られたか分からない場合は、1回と数えます。
  - 開始に失敗した記録は、業者の利用画面で利用が0件であることを確かめたうえで、管理画面の「費用の台帳」で「回数から外す」ことができます（確かめた内容のメモが必須。操作履歴に残る）。台帳の留保と推定も取り消されます。
  - 起動したときに進行中のまま残っていた会話は「再起動で失われた」とし、留保は残します。
- **留保**：会話ごとに、始める前に「最大4分 × 上限の分単価」（GPT-Liveは、裏方のモデルの厳しめの仮定を足す）を台帳に留保します。上限を超えるなら、始めません。
- **終了**：終えたときに、計った時間（画面とサーバーが見た時間の長い方を、課金単位に切り上げ）× 上限の分単価を推定として記録します。**留保は閉じません**（照合待ち）。業者の利用画面の額で照合したときに閉じます（`python3 -m prototype.engines.budget --close …`、または管理画面の「費用の台帳」）。
- **停止**：画面は10秒ごとにサーバーへ知らせ（heartbeat）、サーバーが停止を指示したら接続を閉じます。画面を閉じたときは、終了を送ります。サーバーの見張りは、最大4分＋30秒を超えた会話を期限切れにし、以降の業務処理を断ります。
- **GPT-Liveの終了**：画面は `session.close` を送り、`session.closed` と最終の使用量を最大5秒待ちます。見張りが期限切れにしたときは、サーバーがサイドバンドの接続で `session.close` を送ります。どちらも、`session.closed` が届かなければ「終了・使用量は未確認」と記録し、留保を残します（実接続では未確認）。
- **Geminiの終了**：サーバーから接続を切る方法はありません。接続情報は1回だけ使え、開始から最大時間＋1分で使えなくなるように発行します。
- 台帳とアプリ内の制限は、こちら側で会話を止める仕組みで、業者側の課金の上限を保証するものではありません。

**レビューで指摘された2件の修正（有料の実行より前に修正済み）**

| 問題 | 修正の前（再現） | 修正の後 |
| --- | --- | --- |
| ① 照合額の二重計上：実績$0.03がある留保を、合計$0.05で照合 | 集計が **$0.08** | 集計が **$0.05**（差額$0.02を調整として記録。照合の前の額と利用画面の額を残す。同じ照合を二度しても増えない。違う額は拒否） |
| ② 遅れて届いた使用量のひも付け：割り込みの後、第1発話の応答が使用量なしで遅れて届く | 第1発話の留保が**閉じ**、第2発話の留保が**残った**（逆） | 第1発話の留保が**残り**、第2発話は閉じる（入力の `item_id` と応答の `response.id` で、発話ごとの留保にひも付ける） |

- 回帰試験として、次を加えました。
  - 部分実績の後の照合
  - 実績より少ない照合額
  - 照合の重複
  - 2発話の割り込みと、逆順に届く完了イベント
  - 応答の実績はあるが、文字起こしだけ欠ける
  - 文字起こしが届かない
  - 同じイベントの重複
  - ひも付けできない使用量の保持
  - 実績が留保を超えたときの停止
- 上限の見積もりは、実行の設定とそろえました。
  - 応答の長さの上限：`max_output_tokens` を1,200に設定。
  - 1発話の応答の数：関数呼び出しの後の応答も含めて、3回まで。
  - 1応答の上限額：出力の上限と、対話の時間の上限（180秒）から出す履歴の上限を、すべてキャッシュなしの単価で計算。
- 実績が留保を超えたら、記録したうえで、次の発話の前に止めます。

## 7. 止める条件

- 台帳の上限、または開始の回数に達した。
- サーバーが停止を指示した（AIの拒否、業務処理の回数、GPT-Liveの裏方の応答の回数、最大時間）。
- 業者の認証・権限の誤り（4xx）が出た。
- 1回の会話の費用が、上限の分単価で見た額を超えた（照合のときに確かめる）。
- 架空ではない情報が会話に入った。
